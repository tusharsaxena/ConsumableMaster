# 02 — Deviations

**Addon:** Ka0s Consumable Master · **Prefix:** `CM-` · **Audit:** 2026-07-18 · **Standard:** v2.7.0 (2026-07-17)

IDs are **stable** — reuse them in future audits for any deviation that persists. Deviations CM-01…CM-23 from the 2026-07-12 (v1.0.0) run are **all remediated** and are not re-listed. New IDs continue the sequence from **CM-24** (retired IDs are never re-purposed). Evidence `file:line` for each is in `03_EVIDENCE.md`. Severity is the strongest marker the violated rule carries (**MUST** / **SHOULD**).

| ID | Section (`filename-§N`) | Sev | Deviation | Fix direction |
|----|-------------------------|-----|-----------|---------------|
| **CM-24** | `events-frames-taint-§8`, anti-pattern #35 | MUST | `KCM.SafeToString` detects a combat "secret" with `pcall(tostring, v)` — but a secret **survives `tostring`**, so the probe reports it safe and passes it straight into `string.format` in the debug sink. Detection MUST probe `table.concat`. | Replace the `tostring` probe with a `table.concat`-based `IsConcatSafe` (per the standard's reference `NS.IsConcatSafe`/`NS.SafeToString`); return `"<secret>"` only when a real concat would reject the value. |
| **CM-25** | `events-frames-taint-§8`, `slash-commands-§4` | MUST | Chat output is not funnelled through **one** shared secret-safe printer. Three seams coexist (`KCM.Say`, the file-local `say` in SlashCommands, and ~32 direct `print(KCM.PREFIX .. …)` sites in `settings/Panel.lua` / `core/Debug.lua`), all hand-writing the `[CM]` tag and none secret-safe (raw `..`/`tostring`). | Make `KCM.Say` the single secret-safe seam (build every line via CM-24's fixed stringifier); route SlashCommands' `say`, the Panel `print` sites, and the Debug fallback through it; delete hand-written tag literals. |
| **CM-26** | `slash-commands-§4` | MUST | Multiple printed chat lines end in a **trailing colon** — the help header, `Available settings:`, `dump targets:`, `priority/stat/aio subcommands:`, and several dump section labels. The no-trailing-colon rule covers every chat line. | Strip the trailing `:` from every header/label; introduce lists with the header text alone. |
| **CM-27** | `slash-commands-§5` | MUST | `/cm list`/`get`/`set` output is uncoloured plain text — missing the mandated scheme (header green `33ff99`, `[page]` azure `3399ff`, key gold `ffff00`, value white `ffffff`) and the single shared `FormatKV` + value formatter that `list` and `get`/`set` must share. | Add a shared coloured `key = value` formatter and a shared value formatter; colour the `Available settings` header and `[page]` group headers; reuse across `list`/`get`/`set`. |
| **CM-28** | `slash-commands-§3` | MUST | The `version` verb prints `version <v>` (via `say`), not the canonical single-line `<tag> v<version>`, and reads only the in-code `KCM.VERSION` constant rather than TOC metadata (`GetAddOnMetadata(NS.name, "Version")`) with the constant as fallback. | Print `[CM] v<version>`; read the version from `C_AddOns.GetAddOnMetadata`/`GetAddOnMetadata` with `KCM.VERSION` fallback. |
| **CM-29** | `options-ui-§2` | MUST | The combat-lockdown panel-open refusal prints an **untinted**, non-canonical notice (`cannot open settings during combat. Try again after combat ends.`) at both `O.Open` and the `SetRenderer` OnShow guard. The rule mandates a single `NS.PREFIX`-tagged **grey** notice with the canonical text *"cannot open settings during combat — Blizzard's category-switch is protected"*. (Refusal behaviour itself is correct — it does not defer-and-replay.) | Emit the canonical grey (`|cff808080…|r`) notice through the shared printer at both sites. |
| **CM-30** | `localization-§4`, anti-pattern #37 | MUST | **Tracked / accepted deviation.** `core/TooltipCache.lua` parses **English tooltip text** (`PATTERNS`, `STAT_TOKENS`) for heal/mana/stat magnitudes and effect markers, so magnitude detection is English-only. Classification itself keys on locale-independent `classID`/`subClassID`. Documented as intentional in `docs/scope.md` and `docs/agent-context.md`. | No code change now — keep as a documented, intentional deviation. Full tooltip-text localization is planned for a later release; revisit then. Audit is *expected* to surface it. |
| **CM-31** | `toc-file-§1`, anti-pattern #28 | MUST | TOC metadata **field order** departs from the required order: `Category-enUS` appears before `SavedVariables`/`OptionalDeps`, and `DefaultState` before `OptionalDeps`. Standard order is `… IconTexture → SavedVariables → OptionalDeps → DefaultState → Category-enUS → X-License …`. | Reorder the metadata block to the exact toc-file-§1 field order. Mechanical edit; no code impact. |
| **CM-32** | `toc-file-§1` | MUST | `X-Wago-ID` is absent although the addon is published (ships `X-Curse-Project-ID: 1522944`). The rule requires **both** IDs "once an addon is published anywhere." | Add `## X-Wago-ID: <id>` after `X-Curse-Project-ID`. If the addon is deliberately Curse-only, reclassify as a documented tracked deviation instead (user's call). |
| **CM-33** | `documentation-§2`, `documentation-§6`, anti-pattern #34 | SHOULD | The root `CLAUDE.md` standards section is titled `## Standard — read first` rather than the canonical `## Standards compliance (read first)`. Its substance (stop-and-flag, user classifies deviation-vs-standard-change) is present, but the heading — which the four-place reference rule and audit checklist key on — differs. | Rename the heading to `## Standards compliance (read first)`; keep the existing body. |

**Totals:** MUST = **9** (CM-24, CM-25, CM-26, CM-27, CM-28, CM-29, CM-30, CM-31, CM-32) · SHOULD = **1** (CM-33).
Of the MUSTs, **CM-30** is a pre-existing **documented tracked deviation** (no action expected) and **CM-32** may be reclassified as one at the user's discretion — so **7 MUSTs and 1 SHOULD are net-new actionable gaps**.

**Verdict:** **minor deviations.** The addon is structurally compliant and reference-grade; the open gaps are a cluster of chat-output-seam refinements (CM-24…CM-29) plus three contained edits (CM-31/32/33) and one accepted, documented localization deviation (CM-30). None touch the layout, architecture, schema, tests, or the runtime feature engine.
